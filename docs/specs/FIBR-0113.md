# FIBR-0113 — Show accounts in a sortable 5-column table with an optional number and note

**Status:** spec draft (2026-07-28).
**Kind:** feature.
**Source:** ROADMAP FIBR-0113 (user-request-2026-07-12, screenshot), with
FIBR-0084 folded in (user-request-2026-07-11, dogfooding v0.1.0).
**Pairs with:** FIBR-0084 — this spec unblocks its Accounts half only. It does
**not** close: FIBR-0192 carries the rest and is its blocker (§9).
**Pairs with:** FIBR-0086 — its account-number *storage* half lands here; it
keeps the detection + matching half (§9).

**Layman:** The Accounts tab becomes a proper table — Name, Type, Account
number, Note and Status — that you can sort, resize and reorder, instead of one
cramped line per account; account numbers are hidden behind dots until you ask
to see them, and hide themselves again shortly after.

## 1. Goal

The Accounts tab lists each account as a row in a real table with five sortable
columns — Name, Type, Account number, Note, Status — whose widths and order the
user can change and which finbreak remembers. Two new optional per-account
fields (a reference account number and a free-text note) can be entered and
edited. The account number is masked on screen by default, and a reveal lapses
back to masked after `_REVEAL_SECONDS` without the user doing anything.
Accounts also gains a header for the first time, so it can finally join the
shared remembered-column scheme — one of the three surfaces FIBR-0084 needs;
the other two are FIBR-0192's (§9).

## 2. Problem

`src/finbreak/ui/accounts.py::AccountsWidget` renders accounts into a
`QListWidget`, building one string per row in
`AccountsWidget._refresh()`: `f"{account.name} — {label}"`, then
concatenating up to two suffixes onto it — the remembered-statement-password
marker, and `AccountsWidget._reconciliation_suffix()`'s FIBR-0177 output
(`✓ balances reconcile`, `⚠ off by {money}`, `⚠ {n} periods don't reconcile`).

Four consequences:

1. **Nothing is sortable or scannable.** A list item is one opaque string, so a
   user with a dozen accounts cannot bring the accounts that fail to reconcile
   to the top — which is the only reason that marker exists.
2. **There is nowhere to put an account number.** `models.py::Account` carries
   `id`, `name`, `type`, `created_at` and nothing else, so a user with two
   "Cheque" accounts at different banks has no way to tell them apart.
3. **There is nowhere to put a note.** Same cause.
4. **Accounts cannot join the remembered-column-layout scheme.**
   `src/finbreak/ui/_table_state.py::remember_columns()` already delivers most
   of what FIBR-0084 asks for — `setSectionsMovable(True)`, header
   `saveState`/`restoreState` into the plaintext window INI keyed by
   `objectName`, re-saved on resize / reorder / re-sort — and is already called
   by Statements, Transactions, Rules, Recurring, Transfers and the
   import-wizard preview. A `QListWidget` has no header, so Accounts cannot
   participate at all.

Fixing consequence 4 does **not** finish FIBR-0084. Two further surfaces have
no column persistence either — the Forecast events table and the Home
dashboard's breakdown trees — and Reset layout does not clear saved column
state. Those are FIBR-0192's, which owns the detail and is FIBR-0084's blocker
(§9). `ui/categories.py::CategoriesWidget` is excluded permanently: its
`QTreeWidget` sets `setHeaderHidden(True)` over a single column, so there is
nothing to resize or reorder.

## 3. Scope decisions

Settled with the user on 2026-07-28 (1–5, 7) or by the author from §2 (6):

1. **Five columns, with Status as its own column** — not four columns with the
   markers left glued to the Name cell. Chosen so the reconciliation warnings
   become sortable (consequence 1 above).
2. **The account number is masked by default with an explicit reveal toggle** —
   not shown in full, and not masked with no way to see it. The exposure being
   defended against is shoulder-surfing and screenshots, not storage: the value
   already sits inside the SQLCipher vault, encrypted at rest.
3. **The add/edit form stays inline on the tab**, relaid from one row to a
   two-row grid — not moved into an Add/Edit dialog. Preserves the current
   type-a-name-and-hit-Add flow.
4. **Reveal is session-scoped**, never persisted — a reveal that survives a
   restart is a reveal the user did not ask for that day.
5. **A reveal auto-hides after `_REVEAL_SECONDS`.** Decision 2 defends against
   someone seeing the screen; a reveal left on indefinitely gives that back the
   moment the user walks away, and the app's own auto-lock idle timeout is far
   longer than the few seconds it takes to read a number. A fixed constant, not
   a setting — see §9.
6. **`AccountService.update_account`'s two new parameters are REQUIRED, not
   defaulted** (author). `AccountRepository.update` issues an unconditional
   `UPDATE … SET`, so a defaulted `None` would make every existing
   three-argument call silently erase a stored account number and note. There
   are six such call sites today, listed in §4.2. Required parameters turn each
   into a loud failure instead of silent data loss in a money app — the same
   loud-refusal posture the rest of the codebase takes. §11 records that this is
   only *partly* mechanically caught.
7. **FIBR-0084's remaining surfaces are split out, not carried here** (user,
   after cold-eyes loop 2). Folding them in made this spec the largest source of
   its own review defects. FIBR-0192 owns them; FIBR-0084 stays open until it
   ships.

## 4. Design

### 4.1 Schema — migration v13

`migrations.py::LATEST_SCHEMA_VERSION` becomes 13 and `_MIGRATIONS` gains a
`13:` entry, following `_migrate_to_v11` — the nearest precedent, being the
other nullable `ADD COLUMN` with no backfill. The step carries the same
explanatory docstring every existing step does (all eleven have one):

```python
def _migrate_to_v13(conn: dbapi2.Connection) -> None:
    """v12->v13: add the nullable ``accounts.account_number`` and
    ``accounts.note`` columns for FIBR-0113's columnar Accounts tab. ..."""
    with owned_transaction(conn):
        conn.execute("ALTER TABLE accounts ADD COLUMN account_number TEXT")
        conn.execute("ALTER TABLE accounts ADD COLUMN note TEXT")
        conn.execute("UPDATE schema_version SET version = 13")
```

Both columns are nullable with no default, so SQLite backfills existing rows
with `NULL` in place — no table rebuild, no FK churn. No backfill is possible
or wanted: the data has never been collected. Idempotency is version-gating, as
for every other step: `run_migrations` calls this only for a vault at exactly
v12, so the bare `ALTER`s never replay.

`vault.py::SCHEMA_VERSION` is a **different constant** and stays at 1. It is
the baseline version `create()` stamps on a brand-new vault, which
`run_migrations` then walks up to `LATEST_SCHEMA_VERSION`. Bumping it would
skip every migration step on a fresh vault.

Neither column is length-capped, deliberately. `TEXT` is unbounded, and the
reason is not row count — a single pasted 10 MB note would be unbounded however
few accounts exist. It is that nothing downstream parses, indexes, matches or
aggregates either field: both are inert display/reference strings rendered into
one table cell. The cost of a pathological value is therefore a wide column the
user can resize, not a slow query or a broken import.

### 4.2 Model, repository and service

`models.py::Account` gains two optional fields **appended after `created_at`**:

```python
@dataclass
class Account:
    id: int
    name: str
    type: str
    created_at: str
    account_number: str | None = None
    note: str | None = None
```

`repositories/accounts.py::AccountRepository` builds `Account(*row)`
positionally in both `list_all()` and `get()`, so both SELECTs grow the two
columns **in dataclass field order** — `id, name, type, created_at,
account_number, note` — and `add()` / `update()` grow the two parameters.
`statement_pdf_password` stays out of every listing SELECT, as today: it is
reached only through the dedicated `get_pdf_password` / `set_pdf_password` /
`ids_with_pdf_password` accessors (FIBR-0128 INV-1).

`AccountRepository`'s own writers grow the columns, both with the parameters
**required** — the repository is the layer that issues the unconditional
`UPDATE … SET`, so a default here would defeat §3 decision 6 one layer below
the service:

```python
def add(self, name: str, type: str,
        account_number: str | None, note: str | None) -> int: ...

def update(self, account_id: int, name: str, type: str,
           account_number: str | None, note: str | None) -> None: ...
```

`services/accounts.py::AccountService` grows the fields on both write paths.
`add_account`'s are optional — its callers create an account that genuinely has
neither field — and `update_account`'s are required:

```python
def add_account(self, name: str, type: str, *,
                account_number: str | None = None,
                note: str | None = None) -> Account: ...

def update_account(self, account_id: int, name: str, type: str, *,
                   account_number: str | None,
                   note: str | None) -> None: ...
```

The **six** existing three-argument `update_account` call sites, all of which
must be updated:

| Call site | Caught by |
|---|---|
| `ui/accounts.py::AccountsWidget._on_update` | rewritten by this spec anyway |
| `tests/features/accounts/test_accounts.py` — four calls | the test run |
| `scripts/seed_demo_vault.py` | **nothing** — see §11 |

Plus one **direct repository** call — `AccountRepository.update` in
`tests/features/accounts/test_accounts.py`'s missing-id no-op test — which the
repository signature change above also breaks, and which is easy to miss
because it does not go through the service.

`_validate` keeps its signature and its single `-> str` return. Optional-field
normalisation is a **separate** module-level helper in the same module, called
by `add_account` and `update_account` **inside the service**, so INV-10 holds
for every caller rather than only for the UI:

```python
def _normalise_optional(value: str | None) -> str | None:
    """Strip, and collapse an empty result to None — so a blank form field is
    stored as SQL NULL rather than "" (INV-10)."""
    return (value or "").strip() or None
```

Neither new field is validated for format — an account number is a reference
the user types, not a matching key — and neither participates in the
duplicate-name check.

### 4.3 Masking

A module-level helper in `ui/accounts.py`:

```python
_MASK = "•" * 4

def _mask_account_number(value: str | None) -> str:
    """Display form: a mask plus the last 4 characters for a value longer than
    4; a bare mask for a value of 1-4 characters (its "last 4" would be all of
    it); an empty cell when there is no number at all."""
    if not value:
        return ""
    return f"{_MASK} {value[-4:]}" if len(value) > 4 else _MASK
```

A `QCheckBox` — `self._reveal`, labelled "Show account numbers" — sits beside
the table. Toggling it calls `_refresh()`, which renders the raw value when
checked and `_mask_account_number(...)` when not. It is constructed unchecked
and its state is never written to `QSettings` or anywhere else.

Checking it also starts a single-shot timer that re-masks on expiry — the same
shape as `ui/_clipboard.py::ClipboardAutoClear`, which auto-clears a copied
amount after a settings-driven delay. Following that precedent — whose own
docstring gives the reason, "the single-shot timer's `timeout` is wired
**directly** to :meth:`clear_if_ours`, so the guard has exactly one
implementation" — the timer's `timeout` wires to a **named method**, not a
lambda:

```python
_REVEAL_SECONDS = 30

self._reveal_timer = QTimer(self)          # parented — dies with the widget
self._reveal_timer.setSingleShot(True)
self._reveal_timer.setInterval(_REVEAL_SECONDS * 1000)
self._reveal_timer.timeout.connect(self._on_reveal_timeout)
```

`self._reveal.toggled` connects to `_on_reveal_toggled`, which does three
things: calls `_refresh()`, starts the timer when the box went on, and stops it
when it went off — so unchecking by hand leaves no pending timer to fire over a
later reveal. `_on_reveal_timeout` only unchecks the box, so the re-mask travels
that same path as a manual uncheck — one code path, not two. The interval is
restarted, not extended, on each fresh reveal, and a `_refresh()` reached any
other way does not touch the timer (INV-11).

The timer is a **convenience bound on exposure, not a security boundary** — a
revealed number is on screen for up to `_REVEAL_SECONDS` regardless, and
anything that can read the process's memory can read the value whether it is
masked or not.

Reveal cannot outlive a lock without any extra code:
`main_window.py::MainWindow._lock()` calls `_clear_live()`, which destroys the
whole workspace (its INV-3), and `_build_workspace()` constructs a fresh
`AccountsWidget` on the next unlock — so the checkbox returns to unchecked.
This is a property to *test*, not to implement.

### 4.4 The table

`AccountsWidget._list` (`QListWidget`) becomes `AccountsWidget._table`
(`QTableWidget`), built the way `ui/statements.py::StatementsWidget` builds
`statements_table` — the closest sibling, also five columns:

```python
self._table = QTableWidget(0, 5)
self._table.setObjectName("accounts_table")
self._table.setHorizontalHeaderLabels([
    self.tr("Name"), self.tr("Type"), self.tr("Account number"),
    self.tr("Note"), self.tr("Status"),
])
self._table.setEditTriggers(QAbstractItemView.EditTrigger.NoEditTriggers)
self._table.setSelectionBehavior(QAbstractItemView.SelectionBehavior.SelectRows)
self._table.setSelectionMode(QAbstractItemView.SelectionMode.SingleSelection)
enable_sorting(self._table)      # before remember_columns, as in the sibling
remember_columns(self._table)
```

`_refresh()` is rewritten to fill five cells per row inside
`_table_state.fill_guard(...)`, calling `_table_state.tag_row(table, row, index)`
per row against a new parallel `self._rows: list[Account]`, and — like
`StatementsWidget.refresh` — **ending with an explicit `self._on_selection_changed()`**
so the Forget button's enabled state cannot be left stale after a repopulate
(the FIBR-0128 D3 gating depends on that handler running when the selection
clears).

Row-identity handling follows the `_table_state` contract the sibling tabs use,
because sorting breaks a naive visual-row lookup:

- `_on_selection_changed`, `_on_update`, `_on_delete` and `_on_forget_password`
  resolve the target through `_table_state.selected_index(self._table)` into
  `self._rows`, replacing today's `self._list.currentItem()` +
  `item.data(_ACCOUNT_*_ROLE)` reads. These four are the complete set of
  `currentItem()` readers; `_on_add` correctly has none. The four
  `_ACCOUNT_*_ROLE` constants and their `setData` calls are deleted.
  `self._rows` carries three of the four facts — id, name and type are all on
  `Account`. The fourth is **not**: the has-a-saved-statement-password flag
  behind `_ACCOUNT_HAS_PW_ROLE` comes from
  `AccountService.account_ids_with_pdf_password()` and deliberately does not
  live on `Account` (INV-4 keeps the credential out of every listing). So
  `_refresh()` also stores `self._with_pw: set[int]` from that same call, and
  `_on_selection_changed` gates the Forget button on
  `account.id in self._with_pw`. Dropping this member silently disables the
  FIBR-0128 D3 gating that the paragraph above requires to keep working.
- `_select_account(account_id)` **maps the id to a position first**:
  `select_by_index` matches the insertion index written by `tag_row`, not a
  database id, and the two are not interchangeable. It finds the index of the
  `Account` in `self._rows` whose `id` matches, calls `select_by_index` with
  that index, and selects nothing when the id is absent.
- The selection signal moves from `currentItemChanged` to the table's
  `itemSelectionChanged`.

The Status cell is a `_table_state.SortableItem` whose sort key is a severity
rank, so clicking the header groups problems rather than ordering strings:
`0` = `ReconciliationStatus.OFF`, `1` = the quiet statuses
(`NOT_ENOUGH_DATA` / `NOT_SUPPORTED`), `2` = `RECONCILED`. Its text composes the
reconciliation marker and the 🔑 saved-password marker in that order, joined by
`" · "` and omitting absent parts:
`" · ".join(part for part in (recon_text, key_text) if part)`. That order is a
**deliberate reversal** of today's list line, which appends the 🔑 marker first
and the reconciliation suffix second: the column is sorted by reconciliation
severity, so the reconciliation text leads the cell it is sorted by.

Those marker strings live in four `self.tr(...)` literals in
`_reconciliation_suffix()` and `_refresh()`, each currently beginning with a
`"  ·  "` separator for list-line concatenation. Moving them into a cell means
**editing those four translatable literals** to drop the leading separator —
translation-catalogue churn, not a `removeprefix` hack at the call site.

The other four cells are plain `QTableWidgetItem`s: Name, Type and Note sort
lexically, which is correct. The Account number column sorts by whatever is
displayed — the last 4 while masked, the full value while revealed — so
toggling reveal can reorder a live sort on that column. That is acceptable and
noted rather than fixed; sorting a masked column can only ever expose what the
mask exposes.

### 4.5 The form

`add_row` (today one `QHBoxLayout` of name / type / Add / Update) becomes a
`QGridLayout` of two rows: Name and Type on the first, Account number and Note
on the second, with Add and Update at the end of the second row. Both new
`QLineEdit`s get `setAccessibleName` alongside their placeholder, matching the
existing `_name` field — a placeholder disappears on typing and is not a
reliable accessible name (WCAG 1.3.1 / 3.3.2). `_on_selection_changed`
populates all four fields when an account is selected and **leaves them
untouched when the selection clears** (matching today's behaviour, so a
repopulate does not wipe half-typed input); `_on_add` clears all four; `_on_add`
and `_on_update` pass the raw field text to the service, which normalises it
(§4.2).

Toggling reveal repopulates the table and therefore drops the current
selection. **`_on_reveal_toggled` alone** re-selects the previously-selected
account through `_select_account`, so revealing does not silently reset the form
and the Forget button. `_refresh()` itself does **not** re-select — doing so
would make `_on_add`'s field-clearing useless, because the re-selection would
fire `_on_selection_changed` and immediately repopulate the form with the
account just added.

## 5. Invariants

- **INV-1** — A vault at v12 upgrades to v13 in place, gaining exactly
  `accounts.account_number` and `accounts.note`, both nullable, with every
  pre-existing account row still present and its other columns unchanged.
  *Test:* `tests/features/accounts/test_migration_v13.py`.
  *Breaks when:* the step rebuilds `accounts` (CREATE / COPY / DROP / RENAME)
  instead of issuing two `ADD COLUMN`s, dropping rows or breaking the
  `transactions.account_id` and `statement_periods` FK targets.

- **INV-2** — `LATEST_SCHEMA_VERSION == 13` and `13 in _MIGRATIONS` — the
  constant and the dispatch table agree.
  *Test:* `.venv/bin/python -c "import sys; sys.path.insert(0,'src'); from
  finbreak.migrations import LATEST_SCHEMA_VERSION, _MIGRATIONS;
  print(LATEST_SCHEMA_VERSION, 13 in _MIGRATIONS)"` → `13 True`.
  (Run 2026-07-28 against pre-implementation source: `12 False` — red, as it
  must be before the work.)
  *Breaks when:* the constant is bumped without registering the step —
  `run_migrations`'s `for target in range(current + 1, LATEST + 1)` then
  indexes `_MIGRATIONS[13]` and raises `KeyError` on **every** vault open and
  every vault create, so the app cannot start at all. The reverse (a step
  registered without bumping the constant) is silent: the loop never reaches
  it and the columns never appear.

- **INV-3** — `Account`'s field order and the SELECT column order in both
  `AccountRepository.list_all()` and `.get()` agree, so positional
  `Account(*row)` construction assigns each column to the field of that name.
  *Test:* `tests/features/accounts/test_accounts.py`, asserting a saved
  account reads back with `account_number` and `note` equal to what was
  written — by field name, on both read paths.
  *Breaks when:* a column is appended to one SELECT but not the other, or
  inserted before `created_at` in one of them — e.g. `SELECT id, name, type,
  account_number, created_at, note`, which lands `created_at`'s timestamp in
  the `account_number` field and raises nothing.

- **INV-4** — No account-listing query selects `statement_pdf_password`; the
  remembered credential is reachable only through the three dedicated
  accessors (re-asserts FIBR-0128 INV-1, which has no source-level test).
  *Test:* `tests/features/accounts/test_accounts.py`, walking
  `repositories/accounts.py` with `ast.parse` and asserting the column name
  appears only inside the `get_pdf_password` / `set_pdf_password` /
  `ids_with_pdf_password` function bodies — an AST walk, because a substring
  scan cannot attribute a hit to its enclosing function.
  *Breaks when:* someone widens the `list_all` SELECT to render the 🔑 marker
  directly instead of calling `ids_with_pdf_password()`, putting every stored
  statement password into every account listing.

- **INV-5** — `_mask_account_number` returns a mask plus the last 4 characters
  for a value longer than 4, a bare mask with no digits for a value of 1–4
  characters, and an empty string for `None` or `""`.
  *Test:* `tests/features/accounts/test_accounts.py`, over
  `_mask_account_number` — `"1234567890"`, `"1234"`, `"123"`, `""`, `None`.
  *Breaks when:* the helper slices `value[-4:]` unconditionally, so a 3-digit
  number renders in full — the mask leaks exactly the values it is shortest
  for.

- **INV-6** — A freshly constructed `AccountsWidget` has reveal off, and the
  toggle's state is written to no persistent store, so it cannot survive an
  auto-lock or a restart.
  *Test:* `tests/features/accounts/test_accounts.py` — a `qtbot` test
  asserting the checkbox is unchecked on construction, and that toggling it
  leaves the window INI byte-identical apart from the `columns/` group (which
  `remember_columns` may write from the repopulate). Byte comparison, not a
  key-name search: "no key encodes the reveal state" is not falsifiable as a
  search, since a boolean could be stored under any name.
  *Breaks when:* the toggle is persisted next to the column state in the
  window INI, so a machine left revealed stays revealed across a lock.

- **INV-7** — After the user sorts by any column, Update, Delete and Forget
  statement password act on the account the user has selected, not on the
  parallel-list entry sitting at that visual row index.
  *Test:* `tests/features/accounts/test_accounts.py` — fill several accounts,
  sort descending by Name, select a row, assert the resolved account is the one
  displayed there.
  *Breaks when:* a handler reads `self._table.currentRow()` as an index into
  `self._rows` instead of calling `_table_state.selected_index`. This is the
  money-adjacent one: it deletes the wrong account silently.

- **INV-8** — The table's `objectName` is `accounts_table`, distinct from every
  other table passed to `remember_columns`.
  *Test:* `tests/features/table_state/test_table_state.py`, extending the
  existing objectName coverage.
  *Breaks when:* the `objectName` is left unset, so the saved header state
  lands under the empty `"columns/"` key shared with any other unnamed table
  and the two cross-corrupt each other's layout — the FIBR-0012 defect.

- **INV-9** — The Status column orders by reconciliation severity, not by its
  rendered string: sorting ascending puts every `OFF` account above every
  `RECONCILED` one.
  *Test:* `tests/features/accounts/test_accounts.py`.
  *Breaks when:* the cell is a plain `QTableWidgetItem`, so `"⚠ off by R2.00"`
  and `"✓ balances reconcile"` order by codepoint and the warnings scatter.

- **INV-10** — A blank account number or note is stored as SQL `NULL`, not as
  an empty string.
  *Test:* `tests/features/accounts/test_accounts.py`, asserting
  `account_number IS NULL` after saving with the field left empty.
  *Breaks when:* the form's raw `text()` reaches the repository without
  `_normalise_optional`, so `""` is stored and any later `IS NOT NULL` check
  counts a blank field as filled.

- **INV-11** — A reveal re-masks on its own after `_REVEAL_SECONDS`; switching
  it off by hand cancels the pending timer so it cannot fire across a later
  reveal; and a `_refresh()` from any other cause leaves the pending interval
  untouched rather than extending it.
  *Test:* `tests/features/accounts/test_accounts.py` — a `qtbot` test driving
  the widget's timer directly rather than waiting `_REVEAL_SECONDS` in real time.
  *Breaks when:* the timer is left repeating instead of single-shot, or is not
  stopped on a manual uncheck — a stale timer then re-masks a reveal the user
  started seconds ago, and the box appears to toggle itself. Or `_refresh()`
  restarts it, so editing accounts holds a reveal open indefinitely.

- **INV-12** — Typing an account number and a note into the form and pressing
  Add stores both; re-selecting that account repopulates both form fields with
  the **normalised stored value** (`_normalise_optional` strips, so `" 1234 "`
  comes back as `"1234"` — not verbatim what was typed).
  *Test:* `tests/features/accounts/test_accounts.py` — a `qtbot` test typing
  into both new fields, adding, re-selecting the row, and asserting both the
  cells and both form fields carry the typed values.
  *Breaks when:* the two `QLineEdit`s are built and laid out but never read by
  `_on_add` / `_on_update`, or never written by `_on_selection_changed`. Every
  other invariant here passes in that state — the user types a note, presses
  Add, and it vanishes with no error.

- **INV-13** — **WITHDRAWN** (2026-07-28, cold-eyes loop 2). Covered the
  Forecast events table joining the shared column scheme. Moved to FIBR-0192
  with the §3 decision 7 split. Not renumbered, and not reused: §13's loop-1
  row cites this id.
  *Test:* none — a withdrawn invariant asserts nothing. FIBR-0192 carries it.

- **INV-14** — **WITHDRAWN** (2026-07-28, cold-eyes loop 2). Covered Reset
  layout clearing saved column state. Moved to FIBR-0192 with the same split.
  Not renumbered, and not reused.
  *Test:* none — a withdrawn invariant asserts nothing. FIBR-0192 carries it.

- **INV-15** — `_select_account(account_id)` selects the row displaying that
  account, whatever the current sort order — it resolves the id to a position
  in `self._rows` rather than passing the id to `select_by_index`, and selects
  nothing for an unknown id.
  *Test:* `tests/features/accounts/test_accounts.py` — fill several accounts,
  sort descending by Name, call `_select_account` with a known id, assert the
  selected row's Name cell is that account's; then call it with an absent id
  and assert nothing is selected.
  *Breaks when:* the id is passed straight to
  `_table_state.select_by_index`, which matches the **insertion index** written
  by `tag_row`. Ids are 1-based database keys and indices are 0-based
  positions, so the two silently disagree: the edit form is pre-loaded from a
  different account than the one the caller asked for. INV-7 does not catch
  this — it covers the handlers that resolve *out of* a selection, not the one
  that creates one.

## 6. Failure modes

- **The schema bump breaks unrelated tests — 14 files, not 10.** The version is
  pinned two distinct ways, and a grep for one misses the other:
  `LATEST_SCHEMA_VERSION == 12` assertions, and direct
  `SELECT version FROM schema_version` reads compared against `12`. Between
  them they appear in `accounts`, `backup`, `categories`, `categorisation`,
  `db_performance`, `forecast`, `import_`, `ofx_import`, `pdf_import`,
  `recurring`, `reconciliation`, `spending_alerts`, `transfers` and `vault` —
  including `tests/features/accounts/test_accounts.py`, the file §7 extends.
  Measured 2026-07-28: **11** lines of the constant-comparison shape and **26**
  of the table-read shape, 37 in total across those 14 files. Four test
  functions additionally encode the version in their **names** and must be
  renamed, not just re-numbered — in `spending_alerts`, `db_performance`,
  `reconciliation` and `forecast`. Comments naming `v12` (e.g. "migrates
  straight to latest (v12)") need the same sweep and no grep for either
  assertion shape finds them. Expected churn rather than breakage — the guards
  keep their meaning — and exactly the cost FIBR-0144 exists to remove.
- **Existing widget tests break on the `QListWidget` → `QTableWidget` swap.**
  `tests/features/reconciliation/test_reconciliation_marker.py` walks
  `widget._list`, as do several legs of `tests/features/accounts/test_accounts.py`.
  Two of those legs read `item.data(Qt.ItemDataRole.UserRole)` as the account
  id — and `_table_state._ROW_INDEX_ROLE` **is** `Qt.ItemDataRole.UserRole`, so
  after the rewrite the same call returns a row index and the assertions go
  quietly wrong instead of failing loudly. Every such leg is re-pointed at the
  table as part of this work (§12).
- **A vault newer than the app.** Unchanged behaviour: `run_migrations` already
  refuses a vault whose version exceeds `LATEST_SCHEMA_VERSION` with an
  upgrade-finbreak message.
- **Migration interrupted mid-step.** `owned_transaction` makes the two
  `ALTER`s and the version stamp one atomic unit, so a crash leaves a
  re-openable v12.
- **A backup restored from an older vault.** `services/backup.py` compares
  against `LATEST_SCHEMA_VERSION` and migrates on open, so a v12 backup
  restores and upgrades; a backup taken at v13 refuses to restore into an older
  build, as it already does.
- **A stale saved column layout.** `accounts_table` has no saved state on first
  run, so the header takes its defaults. A layout saved by a future build with
  a different column count restores partially — `restoreState` returns `True`
  and leaves the column count alone. There is no escape hatch today: Reset
  layout does not clear column state, which is FIBR-0192's (§9). A user hitting
  this before that ships must delete the `columns/accounts_table` key by hand.
- **The auto-hide timer fires after the widget is gone.** It is parented to the
  widget, so an auto-lock destroying the workspace destroys the timer with it;
  there is no callback into a deleted object.
- **A `_refresh()` while revealed** — triggered by Add, Update, Delete, Forget,
  the reveal toggle itself, or `MainWindow._refresh_tab` on every activation of
  the Accounts tab — re-renders unmasked and does **not** restart the timer, so
  neither editing accounts nor switching tabs can extend the exposure window
  (INV-11).
- **An account number long enough to widen the column.** Masked display is
  bounded at 9 characters, and the column is user-resizable and remembered, so
  a long number costs nothing while masked and is the user's problem to size
  while revealed. A pathologically long **note** (§4.1 imposes no cap) widens
  its column the same way; it is display-only, so the cost is layout, not
  correctness.
- **Sorting with an empty Status cell.** An account with no reconciliation
  marker *and* no saved password renders `""` with severity rank 1, so it sorts
  between the failures and the reconciled accounts rather than clumping at one
  end by string order. An account with a saved password but a quiet
  reconciliation status renders the 🔑 marker alone, still at rank 1.

## 7. Tests

New file `tests/features/accounts/test_migration_v13.py`, mirroring
`tests/features/forecast/test_migration_v11.py` — the nearest precedent, same
nullable-ADD-COLUMN shape. That precedent has **five** legs and this file takes
all five, not three:

1. a fresh vault is v13 and has both columns;
2. a vault at exactly v12 upgrades cleanly with its rows intact. The precedent
   does not hand-write DDL for its starting vault — it calls the shared
   `conftest` v9 builder and then runs the intervening private steps in order;
   reaching v12 means chaining `_migrate_to_v10`, `_migrate_to_v11` and
   `_migrate_to_v12` off that same builder;
3. `13 in _MIGRATIONS` and `LATEST_SCHEMA_VERSION == 13`;
4. **atomicity** — wedge the second `ALTER` through a raising connection and
   assert the vault is still a re-openable v12. §6 asserts this as fact, so it
   needs a leg;
5. **idempotency at latest** — `run_migrations` on an already-v13 vault is a
   no-op. §4.1 asserts this as fact, so it needs a leg.

Locks INV-1, INV-2.

Extensions to `tests/features/accounts/test_accounts.py` for INV-3, INV-4,
INV-5, INV-6, INV-7, INV-9, INV-10, INV-11, INV-12, INV-15 — repository/service
round-trips, an AST scan for INV-4, pure-function coverage for the mask, and
`qtbot` widget tests for reveal, auto-hide, sort-safe targeting, severity
ordering, the form round-trip and id-based re-selection. INV-8 extends
`tests/features/table_state/test_table_state.py`.

`tests/features/accounts/spec.md` already carries two `INV-N` blocks that each
restart at INV-1 (FIBR-0005's and FIBR-0128's). A third restarting block would
give that file three `INV-1`s and make `testing.md`'s per-test
`# INV-N from spec.md` comments ambiguous — that standard expects one
append-only sequence per file, so the existing two-block layout already departs
from it. Rather than propagate the ambiguity, this spec's invariants go in a
third block whose ids are written **prefixed** — `FIBR-0113 INV-1` …
`FIBR-0113 INV-15` — so every reference resolves to exactly one invariant
without renumbering anything that already exists. The conflict with
`testing.md` §4 is noted rather than silently continued.

The FIBR-0005 and FIBR-0128 legs that assert against `QListWidgetItem` are
re-pointed at the table in the same pass (§12).

Per `docs/standards/testing.md`, every one of these is run against
pre-implementation source and seen to fail before the implementation is
written; INV-2's clause has already been run red (`12 False`) and is recorded
in §5.

The `qtbot` legs assert behaviour on a constructed widget; they do **not**
prove the tab renders correctly inside `MainWindow`, which no automated leg
here covers.

## 8. Alternatives considered (and rejected)

- **Four columns, markers left on the Name cell.** Rejected by the user: the
  reconciliation warning stays unsortable, which is consequence 1.
- **Six columns, splitting the password marker from the reconciliation
  marker.** Rejected by the user as too wide for two rarely-set flags.
- **Show account numbers in full.** Rejected by the user — see §3 decision 2
  for the reasoning.
- **Mask with no reveal.** Rejected: a user who needs the full number to pay
  someone would have to open the vault file to get it back.
- **Move editing into an Add/Edit dialog.** Rejected by the user: more work,
  and it adds a click to every edit for a form that still fits on the tab.
- **Defaulting `update_account`'s new parameters to `None`.** Rejected — see
  §3 decision 6; it turns the six existing call sites into silent data loss.
- **A generic column-customisation layer for FIBR-0084.** Rejected: it already
  exists as `remember_columns` and covers six tables. Building a second one
  would be the duplication `coding.md` §1.3 forbids.
- **Convert Categories' tree too, for FIBR-0084 completeness.** Rejected — it
  is one column under a hidden header; see §2.
- **Carrying FIBR-0084's remaining surfaces here** (the Forecast table, the
  Home dashboard trees, the Reset-layout gap). Rejected — see §3 decision 7.

- Finishing FIBR-0084 — the Forecast events table, the Home dashboard breakdown
  trees, and making Reset layout clear saved column state — tracked by

- Making `_REVEAL_SECONDS` user-configurable, as the clipboard auto-clear delay
  already is. **A decision, not a deferral — no follow-up id.** One fixed
  constant is the shortest correct form of what was asked for, and a settings
  key nobody has asked to change is scaffolding. If it is ever wanted it
  follows the existing `clipboard_clear_seconds` pattern exactly.
- Removing the per-bump `LATEST_SCHEMA_VERSION` test churn described in §6 —
  tracked by FIBR-0144.
- **Detecting** an account number on an imported statement and matching it to an
  account — tracked by FIBR-0086. That bullet currently also claims the
  *storage* half ("a new column in the ENCRYPTED vault; schema migration,
  currently v7 -> v8"), which this spec delivers instead; FIBR-0086's bullet is
  amended to say so (§12), or a later implementer re-adds an existing column at
  a stale version. FIBR-0086 plans to normalise numbers (strip spaces/dashes,
  match on trailing digits); this spec stores the value as typed, so that
  normalisation lands with the matching, not here.
- Per-account currency, which would add a sixth column — tracked by FIBR-0087.
  (FIBR-0087's body carries the same stale "schema migration, currently

  because this spec does not deliver any part of FIBR-0087.)

  nothing to resize or reorder.
- Live language switching for the new widgets. This project has no
  `changeEvent` / `retranslateUi` anywhere in `src/finbreak`, so every `tr()`
  string is bound at construction; the labels added here inherit that
  pre-existing behaviour rather than introducing it. Out of scope and not
  regressed.

## 10. Resource cost

Two nullable `TEXT` columns on a table that holds one row per account — a
handful of rows in any real vault, so no cap is needed and none is imposed
(§4.1). No new external dependency, no new build target. One `QTimer` per
`AccountsWidget`, parented to it. The parallel `self._rows: list[Account]` and
`self._with_pw: set[int]` replace per-item `setData` storage of the same facts,
so widget memory is unchanged in shape and bounded by the account count. One
knock-on: `AccountService._validate` calls `list_all()` on every add and update,
which now pulls two extra `TEXT` columns per account — negligible at one row per
account, and noted rather than optimised.
