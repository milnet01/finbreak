# FIBR-0001 — P01 Bootstrap: lint/format/test/security harness

> **Status:** Accepted (2026-07-01) — Phase D cold-eyes clean;
> user signed off "docs ready to code from".
> **Phase:** P01 — Bootstrap. **Kind:** chore. **Source:** planned.
> **Roadmap:** [ROADMAP.md → FIBR-0001](../../ROADMAP.md).
> **Governed by:** `docs/standards/{coding,testing,commits}.md`,
> `docs/security-model.md`.

**Theme:** stand up the build/dev plumbing and the **quality +
security gate** before any feature code exists, so the harness is
proven working and every later phase runs against it.

## Context

This is the first code phase. It ships **zero user-facing
features** on purpose. Its value is that the tooling that judges
all later work — linter, formatter, tests, and the
security scanners the user has made paramount — is known-good and
runs identically in CI and locally. Sibling P01 bullets
(`FIBR-0002` `.gitignore`/secret-leak guard, `FIBR-0003` bundling
smoke-test) are specced just-in-time when their turn comes.

## Invariants (testable)

> These `INV-N` are **local to this spec** (bootstrap-harness
> invariants). They are a separate numbering from the project-wide
> security invariants in `docs/security-model.md § 5`; where this
> spec cites a security invariant it names the doc explicitly
> (e.g. "security-model.md INV-6").

- **INV-1 — One command, all gates, locally.** Running
  `scripts/ci-local.sh` runs **every** stage below and exits
  non-zero on the first failure. Order is cheapest-first by
  convention and is **not** part of the contract — so the assertion
  a conformance test derives from this INV is *"all of these ran"*,
  never *"in this sequence"*. The stages, as the script runs them:

  | # | Stage | Added by |
  |---|---|---|
  | 1 | `ruff check src tests` | P01 |
  | 2 | `ruff format --check src tests` | P01 |
  | 3 | `shellcheck` (see targets below) | `FIBR-0225` |
  | 4 | `actionlint` | `FIBR-0225` |
  | 5 | `bandit -c pyproject.toml -r src -q` | P01 |
  | 6 | `pip-audit` | P01 |
  | 7 | `gitleaks dir .` | P01 |
  | 8 | `mypy` | `FIBR-0061` |
  | 9 | `pytest -m "not perf"` | P01 |

  **The table is the whole list, deliberately** — an earlier form of
  this INV enumerated the six P01 stages and put later additions in a
  separate paragraph, so a conformance test written from the sentence
  passed on a script that had dropped `shellcheck`, `actionlint` or
  `mypy`. One list, or the invariant under-checks the gate by a third.

  `pytest -m "not perf"`: testing.md § 3.4 permits excluding perf
  tests when noisy; this gate excludes them unconditionally.
  Integration tests **do** run in the gate. `FIBR-0003` adds a build
  smoke-test to the same script, **opt-in** behind
  `--build`/`FINBREAK_BUILD_SMOKE=1` — the everyday gate does not
  pass the flag; the dedicated `build-smoke.yml` workflow does.

  **Precondition — not a bare clone.** The script assumes the dev
  environment is already prepared: the `dev` dependency group
  installed, and the three non-pip binaries (`gitleaks`,
  `shellcheck`, `actionlint`) on `PATH`. That preparation is a
  documented setup step (CLAUDE.md "Build and test"), not a gate
  stage; in CI it is exactly what `scripts/ci-setup.sh` provides. On
  a literally fresh clone with no environment the script fails at
  stage 1 — so "runs clean" is always asserted against a *prepared*
  checkout.

  Source: discovery.md "Local CI emulation" (the lint/test spine) +
  security-model.md § 6 (the `bandit`/`pip-audit`/`gitleaks`
  security stages, which originate there, not in discovery's
  three-stage gate).

  **What stages 3–4 cover, stated as selectors rather than counts**
  (a count goes stale the moment a script is added, and nothing
  reports it): `shellcheck` reads **every tracked `*.sh` in the
  repo** — selected via `git ls-files '*.sh'`, not a directory glob
  — **plus the version-controlled `.githooks/pre-push` hook**, which
  has no `.sh` suffix and so is named separately. `actionlint`
  auto-discovers every workflow in `.github/workflows/`, and
  additionally pipes each `run:` block through `shellcheck`, so shell
  bugs embedded in YAML are covered too.

  The `git ls-files` selector is load-bearing, not a style choice:
  the first cut of this stage used `scripts/*.sh` and silently missed
  the seven packaging recipes under `packaging/obs/` and
  `packaging/flatpak/` — the OBS and Flathub **publish** path, i.e.
  precisely the release machinery the stage exists to protect. A
  directory glob must be widened by hand each time scripts appear
  somewhere new, and its staleness is invisible.

  These two stages exist because this machinery is what no other
  stage **lints**: `ruff`, `bandit`, `mypy` and `pytest` all scope to
  `src`/`tests`, and `gitleaks` reads the whole tree but scans for
  secrets, not correctness.

  **Two pin homes, by tool kind.** `shellcheck` and `actionlint` are
  standalone binaries, not pip packages, so they are pinned in
  `scripts/ci-setup.sh` alongside `gitleaks` — a different release runs
  a different rule set over the same files, so an unpinned build can
  pass locally and fail in CI. `mypy` is a pip package and is pinned in
  `pyproject.toml`'s `dev` group like every other Python tool (INV-4).
- **INV-2 — CI runs the identical gate list.**
  `.github/workflows/ci.yml` runs the same stages as
  `scripts/ci-local.sh`, with **one source of truth in two layers** —
  the stage list and the environment each defined exactly once:

  - `ci.yml` runs **inside** `container: python:3.12-slim-bookworm`,
    so there is **no `actions/setup-python` step** (the image ships
    3.12) and **no `pip install` step**. The image pin is
    load-bearing beyond convenience: its glibc (~2.36) is the
    effective floor of the frozen artifacts, so bumping it raises the
    minimum glibc every AppImage/`.exe` user needs (tracked as
    `FIBR-0180`).
  - Its only project-specific steps are: install `git` for checkout,
    `actions/checkout`, then invoke **`scripts/ci-setup.sh`**
    (environment — OS libs, the pinned non-pip binaries,
    `pip install --group dev`, `pip install .`) and
    **`scripts/ci-local.sh`** (the stage list). Neither script's
    contents are restated in the workflow.
  - `scripts/ci-docker.sh` runs the **same image and the same two
    scripts** locally, so a local containerised run and the GitHub
    run install an identical environment. That is what makes "green
    locally" mean "green in CI".

  A build stage is not part of this gate: `FIBR-0003` adds it to the
  script opt-in behind `--build`, and `ci.yml` passes no flag — the
  separate `build-smoke.yml` workflow is what runs it. Source:
  discovery.md.
- **INV-3 — Green on an empty project.** On the bootstrap commit
  (placeholder `src/` + a one-test suite) every stage exits 0:
  `ruff` clean, `ruff format --check` clean, `bandit` 0 issues,
  `pip-audit` 0 known-vulnerable deps, `gitleaks` 0 leaks,
  `pytest` collects the smoke test and reports 0 failed.
  **The suite must not be literally empty:** `pytest` exits **5**
  (`EXIT_NOTESTSCOLLECTED`) when it collects nothing, and
  `ci-local.sh` runs under `set -euo pipefail`, so a zero-test suite
  makes the gate red — which is why `tests/test_smoke.py` is a P01
  deliverable rather than an afterthought. (Verified by running it;
  an earlier wording of this INV said "0 collected", a green
  condition the gate can never reach.) A later upstream CVE can
  legitimately flip the `pip-audit` stage red without any project
  change — that is the gate working, not a regression. Source:
  app-workflow P01 definition.
- **INV-4 — Reproducible, pinned dev env.** `pyproject.toml`
  declares Python `>=3.12` and pins **every** dev tool exactly
  (`==`) in a PEP 735 `[dependency-groups]` table (`dev` group) — at
  P01 ruff, bandit, pip-audit, pytest and pytest-qt; later additions
  are pinned the same way (e.g. `mypy`, `FIBR-0061`). The list is
  **open-ended on purpose**: an earlier wording enumerated five
  names, so a reproducibility check derived from it passed while
  `mypy` floated unpinned. `pyproject.toml` is the list.

  **Pins outside pip count toward this invariant too.** The three
  binaries the gate shells out to — `gitleaks`, `shellcheck`,
  `actionlint` — are not pip packages and are pinned to exact
  releases by `scripts/ci-setup.sh`. Without them "two machines
  resolve the same toolchain" is false in the way that actually
  bites: two machines with different distro `shellcheck` builds run
  **different rule sets over the same scripts**, so one passes where
  the other fails. (`pytest-qt` is pinned now
  but first used at P02 when GUI tests appear.) Refreshing pins to
  latest-stable is a periodic-sweep process rule (global rule
  § 5c), not a P01 exit check. The exact pins serve INV-4's
  reproducibility and do **not** conflict with the latest-stable
  posture (coding.md § 1.5 / global rule § 5) — the sweep refreshes
  the pins to current-stable. Source: INV-4 reproducibility (exact
  pins) + global rule § 5c (refresh cadence).
- **INV-5 — Security stage is non-bypassable in the gate.** A
  deliberately-planted insecure pattern makes `bandit`/`gitleaks`
  fail the gate; removing it makes the gate pass. This proves the
  security stage is wired, not stubbed.

  **The two halves have different scopes, and the plant must respect
  them** — a fixture planted in `tests/` demonstrates only the
  `gitleaks` half and leaves `bandit` green, which reads as a stubbed
  scanner and invites "fixing" the config:

  - `bandit` scans **`src/` only** — the stage is
    `bandit -c pyproject.toml -r src -q`, and
    `[tool.bandit] exclude_dirs = ["tests", ".venv"]` makes test-tree
    fixtures invisible to it by design (testing.md § 3.5 puts rule
    fixtures in `tests/fixtures/<rule>/`). Plant inside `src/`.
  - `gitleaks` scans the working tree, so a fake credential outside
    `.gitleaks.toml`'s allowlisted paths trips it wherever it lives.

  Source: security-model.md T8 (the `bandit`
  insecure-pattern half) and INV-6 (no secret in the repo — the
  `gitleaks` half) + § 6 (the tooling table).
- **INV-6 — Single-test ergonomics.** A named single test can be
  run in isolation (`pytest -k <name>` / `pytest <path>::<test>`)
  and the command is documented in `CLAUDE.md` "Build and test".
  Source: testing.md § 3.2.

## Deliverables

- `pyproject.toml` — project metadata, `>=3.12`, dev-dependency
  group, `[tool.ruff]`, `[tool.pytest.ini_options]` (markers:
  `features`, `integration`, `perf` at P01; later features register
  more — `pyproject.toml` is the list, not this line),
  `[tool.bandit]`, and later `[tool.mypy]` (`FIBR-0061`).
- `src/finbreak/__init__.py` — placeholder package so the linter
  and importer have a target.
- `tests/` — empty but collectable suite (a trivial
  `test_smoke.py` asserting the package imports).
- `scripts/ci-local.sh` — the one-command local gate: the **stage
  list**, defined once (INV-1).
- `scripts/ci-setup.sh` — the shared CI **environment** prep (OS
  libs PySide6 needs, the pinned non-pip binaries,
  `pip install --group dev` + `pip install .`). Called by **both**
  `ci.yml` and `ci-docker.sh`, so the environment — like the stage
  list — has exactly one definition. Without this as its own
  deliverable the prep lands inline in `ci.yml` and is written a
  second time for local container runs, which is the drift INV-2
  exists to forbid.
- `scripts/ci-docker.sh` — reproduce the CI run locally in the same
  image (`ci-setup.sh` then `ci-local.sh`). What makes a green local
  gate mean a green CI.
- `.github/workflows/ci.yml` — CI mirror (INV-2); pinned
  `ubuntu-24.04` (not floating `ubuntu-latest`, per global rule
  § 5a), running inside pinned `container: python:3.12-slim-bookworm`
  (whose glibc is the frozen-artifact floor — `FIBR-0180`) for the
  lint/test/security gate (the build matrix arrives with packaging
  in P13).
- `CLAUDE.md` "Build and test" + "Module map" sections filled in.

## Out of scope

- Any application feature (that's P02 onward).
- The **build smoke-test** stage of `ci-local.sh`. discovery.md's
  "Local CI emulation" lists a build smoke-test as part of the
  gate; that stage is added to the script in `FIBR-0003` (bundling
  smoke-test), not here. This bullet ships the
  lint/format/security/test stages only.
- The multi-OS build matrix and packaging (P13).
- Pre-commit hooks — the gate is the script + CI; a pre-commit
  hook can be added later if desired but is not required here.

## Exit criteria (Definition of Done)

1. `scripts/ci-local.sh` exits 0 on a checkout with the documented
   dev environment prepared — CLAUDE.md "Build and test" (venv,
   `pip install --group dev`, `pip install .`) plus the pinned
   `gitleaks`/`shellcheck`/`actionlint` binaries on `PATH`; in CI,
   what `scripts/ci-setup.sh` provides. Not a bare clone: the script
   installs nothing (INV-1, INV-3).
2. CI is green on the bootstrap commit and runs the same stages
   (INV-2).
3. The INV-5 planted-secret check demonstrably flips the gate
   red, then green when removed.
4. `/audit` and `/code-quality-review` return zero **actionable**
   findings — non-allowlisted, severity ≥ LOW per
   `docs/audit-allowlist.md` — on the same closing pass. At P01 the
   audit scope is all P01-authored files: `scripts/ci-local.sh`,
   `.github/workflows/ci.yml`, `pyproject.toml`, the placeholder
   `src/finbreak/` package, and `tests/` — since no application
   feature code exists yet.
5. User approves closing P01's first item.

**Loop 1 note.** This pass was triggered by an amendment recording the stages
added after P01, and it found that the document had drifted further than the
amendment did. Three of the fixes changed what an implementer would build:
INV-2 described an `actions/setup-python` step and an inline `pip install`

reproducibility check derived from it would pass with `mypy` floating; and

5, and the gate runs under `set -e`) — verified by running it.

The pass also found a real gap in `FIBR-0225` itself: the new `shellcheck`
stage globbed `scripts/*.sh` and so skipped the seven packaging recipes under
`packaging/obs/` and `packaging/flatpak/` — the publish path it claimed to
cover. Fixed in `scripts/ci-local.sh` by selecting via `git ls-files '*.sh'`,
which cannot go stale; all seven were already clean.
