## What was learned

- **The persisted closing balance is stored as-printed**, so its sign
  convention is **not uniform across account types**: asset accounts
  (current/savings) print a canonical balance (matching `amount_minor`),
  but **debt products (credit card / home loan) print the amount owed** —
  the opposite sign (this is exactly why `standard_bank._verify_checksum`
  uses `opening − total` for Family C). So the asset identity
  `C_prev + Σ == C_curr` holds only for cash accounts. v1 was scoped to
  current+savings to ship zero false alarms; debt/investment deferred.
- The half-open `(P_prev, P_curr]` window (FIBR-0171's `sum_after`)
  telescopes cleanly: a txn dated on a node's `period_end` belongs to that
  node's closing, so no double-count across consecutive gaps.
- `RECONCILED` must key on **every** per-pair diff being 0, not the net —
  two offsetting gaps (net 0) are a real discrepancy, not a pass.

## What was deferred

- **FIBR-0179** (filed this phase, planned `fix`): the FIBR-0171 forecast
  anchor (`ForecastService._anchor`) does `balance_minor + roll_minor` (a
  plain `+`) across **all** account types, which is wrong-direction for a
  debt account's owed-convention closing (and folds an owed figure into a
  vault-wide cash total). Surfaced by this feature's D1/D9; verify-first
  when picked up.
- **v2 reconciliation** for debt (owed-convention identity) + investment
  (market-aware) + a per-statement "which period is off" Statements-tab
  column (pairs with FIBR-0038 coverage/gap detection).
- CSV-only accounts (no persisted closing) stay NOT_ENOUGH_DATA until
  FIBR-0178(a)/(d) (manual balance override / CSV balance column).
