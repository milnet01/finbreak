# FIBR-0019 — Master-password recovery via a recovery key

Close **attempted** 2026-08-21 by `/close-phase`; **blocked**. Thirteen
actionable findings folded into **FP02 / FIBR-0307**; the phase remains 🚧
until that closes.

## What changed

- **The key envelope.** The vault stops being encrypted by a password-derived
  key. A random 32-byte DEK is SQLCipher's raw key, and each credential wraps
  its own copy into a slot in a version-2 sidecar. Changing a credential
  re-wraps 32 bytes and never re-encrypts.
- **New modules:** `keywrap.py` (AES-256-GCM; slot name and Argon2id costs as
  AAD), `services/recovery_code.py` (Crockford base32, mod-37 check symbol),
  `services/vault_migration.py` (§ 13's S0–S6 plus the § 13.3 resume ladder),
  `ui/recovery_key.py` (the one-time display, the forced new password,
  Settings' Add / Replace / Remove). **ADR-0011** records the decision.
- **Changed:** `crypto.py` gained the v2 sidecar reader/writer and dispatches
  `load_and_validate_params` on `sidecar_version`; `AuthService` builds the
  envelope at first run, re-wraps slots, dispatches unlock and converts a v1
  vault at its next successful unlock (D2); `UnlockDialog` gained the recovery
  route on the shared FIBR-0095 throttle; `restore_backup` mints a DEK and
  writes a v2 sidecar.
- **Docs:** the fourteen § 11 named — FIBR-0004 INV-7, FIBR-0014 D4, ADR-0003's
  "no password recovery" consequence, security-model §§ 1 and 5, the glossary,
  README, CLAUDE.md's module map, CHANGELOG.

Shipped to `main` as `7e6c11f`; CI green.

## What was learned

- **Thirteen green invariant tests and seven passing mutation checks caught
  none of the thirteen review findings.** That is the headline. The tests
  verify the design; they do not verify the code around it, and every finding
  lives in an edge the spec named but no `INV` covered.
- **INV-2 leg 3 structurally cannot catch the check-symbol defect.** It
  substitutes `I`/`O` inside `payload` and re-appends `check` untouched
  (`test_envelope.py:153`) — so the one position that is broken is the one
  position the test holds fixed. A test can be correct, pass, and be blind by
  construction.
- **A mutation that survives is not evidence the test is vacuous.** Three of
  seven survived a first attempt and all three were defective *mutations*.
  Most instructive: INV-1 leg 2 does not fire on a DEK derived under a *fresh*
  salt, because that is random per vault; it fires on a non-fresh one, which is
  what § 8.1's rejected design actually is.
- **The gate caught a defect the review lanes could not have.** The first
  `offer_recovery_key` used a blocking `exec()` inside a signal handler, which
  *hung* the first-run suite rather than failing it. Nothing static would have
  found that.
- **Two lanes were briefed to prove findings by running them and had no
  `Bash`.** The `review-lane` grant is read-only. Both said so plainly rather
  than working around it, and both marked the affected confidences down. That
  is a defect in the dispatch, not in the lanes; every load-bearing claim was
  re-verified by hand before filing.

## What was deferred

- **FIBR-0308** — INV-11's hint scan looks for 28-symbol candidates, but the
  27-symbol payload alone is the whole credential. A spec change, not a code
  fix, so it is filed rather than folded into FP02.
- **FIBR-0309** — three pre-existing gaps in the sidecar write and its
  parameter validation (`O_CREAT` without `O_EXCL`, no directory `fsync` after
  `os.replace`, no bound on `time_cost` / `parallelism` / the upper end of
  `memory_kib`). All predate this item, confirmed against `f704605`; surfaced
  rather than fixed in passing per `coding.md` § 1.7.
- **FIBR-0302** — annotated: a restored vault's shape has changed, so the
  untested cross-version `.fbk` restore matters more now.
