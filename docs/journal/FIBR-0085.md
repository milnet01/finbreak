# FIBR-0085 — Batch statement import

Closed 2026-08-06. Contract:
[`docs/specs/FIBR-0085-batch-statement-import.md`](../specs/FIBR-0085-batch-statement-import.md).

## What changed

- **`services/batch_import.py`** (new, Qt-free) — every decision the batch
  makes: the SCAN classify/parse/match ladder (CSV / OFX with per-statement
  fan-out / PDF via decrypt → Standard Bank → generic table), the
  stored-password ladder, `cumulative_counts`, the two-directional REVIEW
  re-derivation, both caps, and the per-file RUN step. SCAN and RUN are exposed
  as per-index *steps* rather than loops, so the widget's
  one-file-per-event-loop-turn chain and a headless `while` drive identical code.
- **`ui/import_batch.py`** (new) — the review table: progress indicator during
  SCAN, approval screen during REVIEW, report after RUN.
- **`importers/sniff.py`** (new) — `looks_like_ofx` / `looks_like_pdf`, lifted
  off `ImportWizardWidget` so a headless service could call them without
  importing the UI layer. `default_table_index` moved to `pdf_importer.py` for
  the same reason.
- **`ui/import_wizard.py`** — `getOpenFileNames` with count routing (one file
  still takes the unchanged single-file flow), a fourth stack step *appended* so
  all 24 existing absolute `_stack.currentIndex()` assertions stay true, and the
  scan/ask/run chain armed with the three-argument `QTimer.singleShot`.
- **`ui/account_picker.py`** — a `create_requested` affordance; `PasswordDialog`
  gained an optional `remember_text`.
- **Tests** — `tests/features/batch_import/` (spec.md + a headless and a qtbot
  file, 20 tests). `dialog_lifecycle` extended by a fifth file and the
  `processEvents` token (INV-6).

## What was learned

- **A gate can be green and the feature still broken.** Every static stage
  passed — ruff, bandit, gitleaks, shellcheck, actionlint, zizmor, mypy, plus
  semgrep — and 1855 tests were green, while `Import all` could be pressed
  mid-scan and silently skip half the batch. Nothing mechanical was ever going
  to catch it; two independent review lanes did, separately.

- **The spec's own reasoning had the gap in it.** § 4.6 gated the button on
  `needs_account` alone "because ASK exhausts the other questions first" — a
  property of the *flow*, not of the button, and § 6 and § 4.7 between them
  broke the flow by putting the table on screen from turn one and returning to
  the event loop between turns. Three sections were each individually right.

- **I wrote a vacuous test and the mutation checks did not catch it**, because I
  mutated the implementation the test named and never mutated `can_import`
  itself. Both INV-3 legs used CSVs, so every record stopped at
  `needs_account`, and the gate failed on its "at least one ready" clause alone
  — the exact wrong implementation the spec names as the break passed the whole
  suite. The lesson is that a mutation check only proves what it mutates; a leg
  needs its *precondition* asserted (there IS a `ready` record) as well as its
  conclusion.

- **Two tests needed a second attempt to become honest.** The re-entry test only
  caught the missing phase guard once the second click was *queued* rather than
  called inline — inline, `_run_next`'s own index assignment overwrites the
  rewind and the defect hides. INV-14's cancel-during-run leg raced to
  completion inside `waitUntil` (which pumps the event loop) before the click
  landed. Both now interpose on `run_step`, the way INV-7 already did.

- **Two string replacements silently did not match** after ruff reformatted the
  lines between writing and editing, and I did not notice until a mutation check
  came back green when it should have been red. Every scripted edit since
  asserts its target is present.

## What was deferred

- **FIBR-0252** — `StandardBankImporter.parse` discards `result.errors`, so the
  new Errors column reads 0 for every Standard Bank statement. Pre-existing
  (last touched by FIBR-0086) and out of this change's scope; surfaced only
  because the batch gave the count a screen to appear on. Needs its own
  synthetic fixture and changes the single-file preview too.

## False positives confirmed

None. `docs/audit-allowlist.md` is unchanged — every finding this close
produced was verified real against source, and the two severest were reproduced
by hand before anything was edited.

recorded in the spec's new § 14 rather than edited into the contract.
