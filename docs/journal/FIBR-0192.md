# FIBR-0192 — Reset layout resets columns; Forecast + Home join the scheme

Closed 2026-08-02 by `/close-phase`. Implementation `70f0e15`; fix-pass FP01
(FIBR-0204) `5cd057f`. Gate green **1455 passed, 2 skipped**.

## What changed

- `remember_columns` widened from `QTableWidget` to `QTableWidget | QTreeWidget`
  via a new `_header_of`, which is the whole reason the Home trees could join.
- The build-time header state is captured into a `finbreak_default_header_state`
  dynamic property on the view — a property, not a module registry, so it dies
  with the widget rather than leaking across a workspace rebuild.
- New `reset_columns(root)` sweeps `findChildren` and restores that state. Views
  built without `remember_columns` are skipped.
- `_reset_layout` reordered to resize → centre → `reset_columns` → clear → sync,
  and passed `self` rather than `_workspace` (which is `None` before unlock).
- Two new call sites: `forecast.py::_make_table` and `home.py::_build_column`.
  Forecast deliberately gains **no** click-sorting — its `_fill_events` has no
  `fill_guard`, so a re-sort mid-fill would pair a running balance with another
  event's date.
- FIBR-0084 closed on the back of it; both bullets ✅.

## What was learned

**Two measured "facts" the design rested on were wrong, and both had survived
four cold-eyes loops.** Neither was found by reading; both were found by running
Qt again during the close.

- **QT-10's negative half was read backwards.** `saveState()` *does* serialise
  `stretchLastSection`, the resize mode, `sectionsClickable`, `defaultSectionSize`
  and per-section hidden flags. The probe that "proved" otherwise printed the
  *captured* values after a restore — which is exactly what being in the state
  looks like — and the doc read that as their being absent. Cold-eyes loop 3 then
  cited the misreading to **dismiss a reviewer who had it right**. The fix was to
  stop enumerating safe flags and state the rule instead: `remember_columns` is
  the last header call, full stop.
- **QT-5 was an artefact.** `restoreState` emits `sortIndicatorChanged` and the
  `Qt::SortOrder` marshals cleanly, so `_save` runs and `reset_columns` writes to
  the INI — the opposite of what two shipped source comments asserted. Only
  `_reset_layout`'s trailing clear makes that harmless, which promotes the
  ordering from tidiness to a correctness requirement.

**The lesson that generalises:** a probe's *output* was correct both times and
its *conclusion* was wrong, so every later reader who checked the doc against
itself found agreement. Internal consistency cannot catch this class — only
re-running the measurement can. Worth doing on any PySide6 bump.

**A reviewer's root cause needed checking too.** The review attributed QT-5's
reading to Probe A lacking a `from PySide6.QtCore import Qt`. Tested both ways:
the handler runs either way, so that explanation is recorded in the doc as
disproved rather than repeated. The finding was right; its diagnosis was not.

**A test fix that itself needed fixing.** INV-6's precondition (b) asserted only
that the settings key existed. The first replacement compared the stored bytes
against the build-time default — and mutation testing showed *that also passes*
with the widening removed, because the preceding `window.resize` already provokes
a save. Only snapshotting either side of the widening actually enforces it. A
strengthened assertion is not stronger until a mutation says so.

**Shipping is a documentation event.** The code landed while 15+ passages still
described the item as pending, including the spec's own Status line and one
instruction telling users to delete an INI key by hand because "there is no
escape hatch today". §12 had listed most of these; the list was not worked.

## What was deferred

- **FIBR-0199** (📋 test) — nothing discriminates Reset layout's settings clear.
  `reset_columns` and `settings.remove("columns")` are redundant in-process, so
  only dropping *both* turns INV-6 red. Needs a genuinely fresh process, or a
  fixture that destroys a remembered view before the reset.
- **FIBR-0200** (📋 fix) — `remember_columns`' `_save` closure can outlive its
  header and raise at teardown. Independently reproduced by the close's code
  lane; this change takes the connected closures from 8 to 12. Its body's
  citation of "the QT-5 `TypeError`" was withdrawn here, since that TypeError
  does not exist; the `RuntimeError` it describes is separate and real.

## False positives confirmed

None. No allowlist entries were added — static analysis (semgrep, ruff, bandit)
returned **0** on the changed surface, and every review finding that was verified
turned out to be genuine. One reviewer *explanation* was disproved (the
`QtCore.Qt` import theory above), but its finding stood.
