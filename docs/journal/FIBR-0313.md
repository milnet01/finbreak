# FIBR-0313 (FP04) — close attempted

**Outcome:** blocked. Close ran on 2026-09-06 and did not come back clean;
seventeen actionable findings folded into FP05 (FIBR-0337). FP04 remains 🚧
until FP05 closes.

## How the close was run

`check-code` plus four `review-code` lanes, all from a fresh context per
FIBR-0310's rule, scoped at the recovery-key envelope: `vault_migration.py`,
`backup.py`, `auth.py`, `crypto.py`, `keywrap.py`, `recovery_code.py`,
`ui/recovery_key.py`, `ui/unlock.py`. Lanes were briefed on the contracts and
NOT on FP04's own findings, so a re-surfacing defect would show as new.

`check-code` was clean — ruff, bandit, mypy, semgrep, pyright and vulture all
zero. It earned that by testing the one `nosec` suppression rather than reading
it: stripping the comment made the rule fire again.

## What was learned

**The lanes found what static analysis structurally cannot.** Every one of the
seventeen is a question about intent — does this check answer the question its
caller asks, does this dialog have a way out, does this docstring's guarantee
exist in code. No linter asks those.

**The dominant defect shape is unchanged across three passes:** a check that
folds several distinct answers into one, and a caller acting destructively on
the merged result. FP04's own C1 was that shape; so is FP05's H1, in the same
module. Worth treating as a design property of the resume ladder rather than a
recurring accident.

**Two lanes independently found the same wipe gap**, which is the strongest
signal the run produced.

**Reading was not always enough, and the lanes said so** rather than guessing —
the `OverflowError` escape and the Windows key binding were both reported as
reasoned-not-executed. Both were then verified by running them, and both held.

## What was deferred

Nothing to `docs/known-issues.md`. Two items were recorded by lanes as outside
their slice rather than filed: a regeneration-offer flag set before the forced
password step, and the throttle's behaviour under clock skew.

## False positives confirmed

None added this close. `check-code`'s three candidates were each disposed of by
reading the code rather than by allowlisting: the `nosec` is load-bearing, the
`vulture` hits were an artifact of scoping it to eight files, and the `typos`
hit is the project's house spelling.
