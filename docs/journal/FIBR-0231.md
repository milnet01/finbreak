# FIBR-0231 — Plain-English monthly summary

Closed 2026-08-06. Spec:
[`docs/specs/FIBR-0231-plain-english-month-summary.md`](../specs/FIBR-0231-plain-english-month-summary.md)
(four `/cold-eyes` loops before code). Commits `22625bc` (TDD) → `bbfc2bc`

## What changed

- **`services/month_summary.py`** — the pure `summarise_month` detector plus a
  vault-scoped `MonthSummaryService` that prepares its inputs. Integer minor
  units only; the materiality gate is a cross-multiplication, never a division.
  A **complete** month is compared whole against whole calendar months and only
  a **partial** one truncates, its head capped at `L_min − 1` so a month-end
  debit order is inside all four windows or outside all four. The cause is a
  merchant **family**'s excess over its own baseline, never the largest row, and
  all four windows are read with `drill_rows_in_range` so the baselines carry
  descriptions.
- **`ui/month_summary.py`** — `MonthSummaryStrip`, which owns all 18 templates.
  The service emits facts only, so it stays translation-free.
- **`models.py`** — `MonthVerdict`, `MonthCause`, `MonthSummary`.
- **`ui/home.py` + `ui/main_window.py`** — `month_summary` added as the sixth
  positional parameter, before `amount_prefs`, so no existing positional binding
  shifts. `refresh()` clears the strip as its first statement and reads
  `date.today()` once for the strip and the tiles alike.
- **Tests** — `tests/features/month_summary/` (`spec.md` + four files, 87 tests),
  split by capability per spec § 7. Ripple: six existing `HomeView(` call sites.
- **Docs** — `text.py`'s `merchant_name` docstring now names this as its third
  consumer and **second filter case**; `design.md`'s service list gains
  `MonthSummaryService`.

## What was learned

- **The most valuable review lane was the one that mutated the code.** Three cold
  lanes ran. The arithmetic lane found nothing at any severity and the wiring
  lane found four LOWs — both by reading. The lane that applied 45 targeted
  mutations and watched the suite stay green found **2 HIGH and 6 MEDIUM**, all
  of them tests that could not fail. A suite that is green against the defect it
  names is worse than a missing test, because it reads as coverage; nothing but
  mutation finds that.
- **Two of the vacuous tests were vacuous in ways careful authoring produces.**
  The round-half-up mean leg computed its expected value with a verbatim copy of
  the line under test — an identity, not a test — *and* its fixture's sum was
  `≡ 1 (mod 3)`, the residue where truncation gives the same answer. Both look
  like diligence on the page.
- **A fixture can clear four silence conditions and still pass for the wrong
  reason.** The future-month leg was written with `today` on the 5th; forcing
  `started` true also makes the month *partial*, so condition 3 silenced it and
  the leg passed against its own mutation. Only mutation-proving surfaced it —
  moving `today` to the 15th fixed it.
- **`refresh()`'s first-statement clear did not close every path.**
  `_on_period_changed` **persists** before it re-renders, and that write can
  raise, so `refresh()` is never entered. The spec's "whatever raises, and
  wherever" was false for exactly one ordering. Fixed in code and corrected in
  §4.9 rather than left as drift.
- **§4.8's own gloss was wrong about when the strip first speaks.** Condition 2
  applies a whole-month-sized floor to a *truncated* baseline, so it binds before
  condition 3: a R100/day vault first speaks on day 10, not the 7th, and under
  ~R4,300/month the current-month strip never renders. Behaviour kept, claim
  corrected.
- **Two agents sharing one working tree faked a flaky test.** A lane running
  `pytest` reported unreproducible INV-13 failures; a concurrent lane was
  mutating `ui/home.py` at the time. 70 reproduction runs found nothing because
  there was nothing to find. Mutation-testing lanes need worktree isolation.
