# FIBR-0172 — Spending alerts (journal)

Closed 2026-07-24 by `/close-phase`. Self-directed (user delegated the
pick and asked to run autonomously).

## What changed

- **`models.py`** — `AlertKind` (new_recurring / category_spike /
  missed_debit) + `SpendingAlert` dataclass.
- **`services/alerts.py`** (new) — three prepared-input dataclasses +
  three **pure, integer-only** detectors (`detect_new_recurring`,
  `detect_category_spikes`, `detect_missed_debits`) + `AlertService`
  (prepares inputs, does the sole `Decimal→minor` conversion, orders,
  filters dismissed). (a) fires for a suggested OUT stream with
  `occurrences ≤ 4`; (b) for a category whose last **complete** month is
  ≥ 2× its prior-3-month integer average (confirmed-transfer +
  uncategorised excluded, so totals match the dashboard donut); (c) for a
  confirmed OUT stream overdue past `next_expected + 3 days`.
- **`migrations.py`** — schema **v12** `alert_dismissals`
  (`alert_key TEXT UNIQUE`), the `recurring_decisions` idiom.
- **`repositories/alert_dismissals.py`** (new) — idempotent `dismiss`
  (`ON CONFLICT DO NOTHING`), `dismissed_keys`, `clear`.
- **`ui/home.py`** (+ `main_window.py`) — a non-intrusive `AlertsCard`
  above the selectors (hidden when empty), per-row Dismiss buttons, a
  `VaultLockedError`-silent handler with a **card-local** rebuild; the
  view builds the translated strings, the service returns structured data.
- **Tests** — `tests/features/spending_alerts/` (33 tests, INV-1..19),
  reproduce-first.
- **Drift ripple** — bumped the schema-version guards across 12 feature
  test files and **reworked** (not renumbered) the FIBR-0177
  reconciliation guard.

## What was learned

- **Gate "new" on `occurrences`, not a date window.** The first draft
  used `first_seen ≥ today − k·nominal_interval`; cold-eyes found the
  per-cadence accept band lets day-gaps exceed the nominal interval, so a
  freshly-detected *monthly* stream's worst-case `first_seen` fell
  **outside** any fixed-`k` nominal window — the flagship "new
  subscription" case would silently never fire, behind a green test.
  `occurrences ≤ 4` is cadence-agnostic and has no boundary to get wrong.
- **A new table's schema bump ripples other features' guards.** Adding
  `alert_dismissals` (v12) broke FIBR-0177's `test_no_schema_change.py`,
  which asserted `12 not in _MIGRATIONS` — a blind `== 11 → 12` sweep
  can't fix that line. It had to be **reworked** (rename, re-aim at
  `LATEST + 1`, fix docstring + spec prose), not renumbered.
- **Keep the pure detectors `Decimal`-free by converting in the service.**
  `RecurringItem.amount` is a `Decimal`; doing the `→ minor` conversion in
  `AlertService` input-prep (not the detector) is what keeps INV-15 true
  for the (a)/(c) paths.

## What was deferred (§6, v2)

- New recurring **income** alerts (v1 is OUT-only).
- A **real-time** (day-of-month-clipped) category spike instead of the
  last-complete-month comparison.
- **Configurable thresholds** in Settings (the constants live in one
  module for that).
- A **currency-aware** `_MIN_BASELINE` (v1 is a digit-count floor).
