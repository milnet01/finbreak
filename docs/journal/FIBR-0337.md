# FIBR-0337 (FP05) — closed

**Outcome:** clean. Every finding fixed, gate green. FP05 closes, and with it
the chain FIBR-0019 → FP02 → FP03 → FP04 that had been open since the first
close attempt.

**`/close-phase` was NOT run.** It would have produced FP06 — the fifth
consecutive fix-pass — which trips this project's convergence checkpoint. The
checkpoint exists to force that call, so the recurring shape is filed as
FIBR-0339 rather than patched again.

## The two that mattered

**H1 — data loss.** The resume ladder's branch 2 folded "this replacement is
bad" and "I cannot compare it" into one `False`, then deleted a proven-good
migrated vault on the second. `_replacement_verdict` keeps the answers apart;
`UNCOMPARABLE` keeps the copy and refuses rather than falling through.

The design note written before the fix was right that the obvious remedy fails
alone: `_convert` opens S1 by unlinking the migrating database, so a fix that
only skips branch 2's unlink loses the file moments later. `mutation_probe`
confirms both the original defect and that near-miss go red against the test,
which asserts survival across the whole `resume` call rather than across
branch 2.

**H2 — no exit.** D6 makes Escape and the window [X] no-ops, so the forced
new-password dialog's only way out was `StandardKey.Quit` — which resolves
through the platform's binding scheme and is Ctrl+Q only under KDE and Gnome.
Both call sites now spell it literally. The defect cannot reproduce here, so
the test stands in a hostile binding scheme instead.

## What the rule-14 gates added

Two contract documents were amended, so the gate was owed on each. Both ran to
this project's cap and both capped calm.

They found defects the fix pass did not. All three spec lanes caught § 13.2's
S6 stating its two steps in the order `_finish` documents as the UNSAFE one:
`migration_pending` is the only thing that brings the ladder back to S6, so
clearing it before the unlink and then failing strands an encrypted copy that
still opens under the master password of the moment, with nothing that ever
retries. INV-1's test could not exclude § 8.1's rejected design and now has a
leg that `mutation_probe` proves kills it. INV-2 claimed Argon2id's own minimum
pins iterations and parallelism, which it does not.

## What was learned

**A fix can make a previously-inert finding material.** Loop 1 of the
security-model gate dismissed a wrong-owner citation as true-but-inert — rule
14's own example of a finding that changes nothing. That loop's fix then added
a second citation naming a different owner for the same decision, and the next
loop's lanes filed it. The dismissal was correct when made and wrong afterwards,
because of the fix.

**Lanes catch the orchestrator's errors when the packet states facts.** Two
lanes independently disputed a packet fact of mine — that
`validate_untrusted_params` bounds every cost axis on both sides; it caps
memory on the high side only. Both declined to file it against the document,
one saying outright not to correct the document toward the packet. A fix had
inherited that error, and the dispute is what found it.

**The defect shape is a design property, not an accident.** FP02, FP03 and FP04
each recorded it, and FP05 found it repeatedly in one pass. The ladder's helpers
return two-valued answers to three-valued questions, and their callers act
destructively on the merged result. `_replacement_verdict` is the first to name
the third answer. FIBR-0339 carries the rest.
