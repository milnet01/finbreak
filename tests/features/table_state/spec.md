# Feature test contract — table state (FIBR-0117)

Enforces the reusable `ui/_table_state.py` behaviour shared by the list tables:
click-a-header to sort (second click toggles ascending/descending), and remembered
column widths across sessions.

| # | Assertion |
|---|-----------|
| 1 | **Numeric sort key.** `SortableItem("112", 112)` sorts *after* `SortableItem("69", 69)` — numerically, not lexically ("112" < "69" as text would be wrong). |
| 2 | **Tag survives reorder.** After `tag_row`, `selected_index` returns the tagged parallel-list index of the selected row — so a row's action target is correct even when the visual order differs from insertion order. |
| 3 | **Action targets the sorted row.** In the Transfers tab, seeding two pairs (100.00, 500.00) then sorting Amount **descending** and confirming the top visual row confirms the **500.00** pair (the sorted row), not the insertion-order first row. This is the correctness guard: a wrong row→action map in a money app is unacceptable. |
| 4 | **Widths remembered.** Resizing a column then rebuilding the widget restores that column's width (persisted to the window settings INI, keyed by the table's objectName — never the vault). |
| 4b | **Sort remembered.** The chosen sort column + direction also persist across a rebuild — the restored header re-sorts the rows (not just the indicator arrow), since header `saveState/restoreState` carries the sort indicator and `fill_guard`'s re-enable re-applies it. |
| 5 | **Sorting is off where order is semantic.** The Rules table (priority-ordered, Move up/down) is **not** click-sortable, but still remembers its column widths. |
| 6 | **Forecast columns are movable + remembered** (FIBR-0192 INV-1). The Forecast events table's header is `sectionsMovable()` after construction — a fresh `QTableWidget` header is not, so this discriminates a missing `remember_columns` — and a resized column round-trips through a rebuild. |
| 7 | **Forecast is not click-sortable** (INV-2). Sorting stays off, and a real left-click on the Merchant header leaves the Date cells in the order `_fill_events` wrote them. The fixture seeds two confirmed recurring items whose merchant order differs from their date order, so a click that *did* sort would be visible. `_fill_events` pairs each row's running balance with its own date and has no `fill_guard`, which is why sorting must stay off. |
| 8 | **Each Home breakdown tree remembers its own columns** (INV-3). The three `dashboard_breakdown_*` trees restore three distinct widths across a rebuild, under three separate `columns/*` keys. Deliberately does **not** assert `sectionsMovable()`: a `QTreeWidget` header is movable by default, so that clause would pass with no call at all. |
| 9 | **Reset layout restores LIVE headers** (INV-5). With a workspace live, a widened + dragged `transactions_table` column returns to its build-time width *and* visual position with no rebuild; the header stays movable; persistence still works afterwards; and the Forecast table — a surface this item adds — is reached too. |
| 10 | **A reset survives a rebuild** (INV-6). After a reset, a freshly constructed view shows default columns. Narrower than it looks: `reset_columns` and the settings clear are redundant in-process, so this goes red only when **both** are dropped, and it does not discriminate the clear-first/clear-last ordering. |
| 11 | **Reset layout is safe with no workspace** (INV-7). Invoked before unlock, where `_workspace` is `None`, it does not raise — `reset_columns` is passed the window, not the workspace. |
| 12 | **A reset restores the BUILD-TIME default, not the saved layout** (INV-8). With a non-default layout seeded into the INI *before* construction, the reset returns the column to its build-time width, not the seeded one; and the row order matches the sort indicator the reset restored (the guard against wrapping the restore in `blockSignals`). |
| 13 | **The settings clear discriminates on its own** (FIBR-0199). Row 10/INV-6 only goes red when BOTH `reset_columns(self)` and `settings.remove("columns")` are dropped from `_reset_layout` — each alone leaves a *live, reachable* view on the default. This row destroys the remembered `transactions_table` (`deleteLater()` + a real event-loop flush — a bare `processEvents()` does not process `DeferredDelete`) BEFORE the reset runs, so `reset_columns(self)`'s `findChildren` has nothing left to restore; only the settings clear can then keep the stale, persisted width from surviving into the next rebuild. |

Every on-disk vault uses `tmp_path`; the column-state INI is redirected to `tmp`
by the autouse `window_ini` fixture, so no test writes the real per-user settings.
| 14 | **`selected_indexes`, and `select_by_index` staying single-row** (FIBR-0201 INV-15). The plural sibling of `selected_index` returns every selected row's tag sorted **by index value**, skips an untagged row, and is empty with no selection — the visual order in the fixture is deliberately the reverse of the insertion order, so an implementation that reads rows top-to-bottom fails. The ordering is normative: it decides which of two conflicting pairs `confirm_many` confirms first (FIBR-0201 INV-4). Separately, `select_by_index` must clear the selection first — `selectRow` *replaces* under `SingleSelection` but *adds* under `MultiSelection` (measured 2026-08-02), so without it the shipped `StatementsWidget._select_period` silently becomes "also select this row". Asserted in both modes, since the helper is shared with two tables FIBR-0201 does not widen. |
